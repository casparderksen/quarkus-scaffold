# Domain-Driven Design (DDD)

Domain-driven design is an approach to software design that centers every
decision on the business domain and on an explicit, shared model of it.

## Why

By aligning code with business reality and naming things as domain experts
name them, DDD reduces the translation loss that creeps in when engineers
and experts speak different languages about the same thing.

## Pillars

Bounded contexts that keep each model coherent, a ubiquitous language shared
by everyone, aggregates that guard consistency, and repositories that
abstract storage away from the model.
